# はじめに

`Golash` は、モダンな文法と厳密なエラー検出を備えた処理系です。

主な特徴は以下のとおりです。

* 同一バイナリで CUI と GUI を切り替えられます。
* `#mode` で実行モードを指定します（特別なビルドは不要です）。
* レジスタ型VMでコンパイルして動作します（中間ファイルを生成しません。`GOLASH_BACKEND=tree` でツリーウォークに戻せますが、観測可能動作は同一です）。
* `if` や `while` などの条件式では、厳密に `bool` 型を要求します。
* 日本語テキストは rune 単位で扱い、日本語も 1 文字として数えます。
* 配列は参照セマンティクスを持ちます。
* `#include`、`#define`、条件付きプリプロセスに対応しています。
* GUIでは描画、入力、音声、ウィジェットなどの機能を利用できます。

# インストールとビルド方法

## 必要環境

Go 1.25 以上が必要です。

## ビルドとテスト

```sh
cd golash
go build ./...
go test ./...
```

コマンド名 `gsh` のバイナリを作る場合は、出力名を指定します。
単一バイナリで CUI / GUI の両方が動作します。

```sh
go build -o gsh .          # Linux / macOS
go build -o gsh.exe .      # Windows
gsh run examples/falling.gsh
```

> `TestGuiRender` など一部のGUIテストは Ebiten の制約により、1プロセスにつき1回だけウィンドウを生成します。2回目以降は自動的にスキップされます。

---

# コマンドの使い方

```text
gsh run <file.gsh> [-- args...]   スクリプトを実行します
gsh repl                                            対話環境（REPL）を起動します
gsh lex <file.gsh>                                  字句トークン列を表示します
gsh parse <file.gsh>                                構文木（AST）を表示します
gsh disasm <file.gsh>                               バイトコードを表示します（VM用）
gsh build <file.gsh> [-o out.exe]                   単一exeを生成します
gsh help                                             ヘルプを表示します
```

既定はレジスタVMバックエンドです（コンパイルして実行）。
環境変数 `GOLASH_BACKEND=tree` でツリーウォークに戻せます。
出力・エラー文言・位置・終了コードは両系で同一です。
`GOLASH_TRACE=1` でVMの命令トレースを標準エラー出力します。

## `gsh run`

```sh
gsh run examples/falling.gsh
```

スクリプトを実行します。

### コマンドライン引数

ファイル名の後に `--` を置くと、その後ろをスクリプトの引数として取得できます。

```sh
gsh run main.gsh -- hello world
```

スクリプト側では `args()` で取得します。

`-` から始まる引数は `--` の後に記述してください。GUIビルドで `--` より前に指定されたオプション形式の引数はエラーになります。

### ファイルの関連付け（ビルドした exe をダブルクリックで開く）

`gsh build` した exe にファイルを関連付けると、そのファイルをダブルクリックしたときに exe が起動し、パスが `args()` の先頭に入ります（例：`main.exe "C:\work\foo.gsh"` → `args()` は `["C:\\work\\foo.gsh"]`）。スクリプト側で先頭を開けば、エディタ等の関連付け起動が作れます。Windows では対象ファイルを右クリック→「プログラムから開く」→ exe を選択します。

## `#mode`

実行モードをコード内で指定します（`gsh run` のみ有効。REPL は常に CUI です）。

```
#mode cli
```

- `#mode cli`：端末で実行します（ウィンドウを開きません）
- `#mode gui`：ウィンドウを開いて実行します
- 省略時：`gui`（ウィンドウを開きます）
- 複数ある場合：有効な行の最後が勝ちます（`#ifdef` の無効分岐内は無視、`#include` 先も対象）

## `gsh repl`

REPLを起動します（常に CUI。`#mode` は無視されます）。

```sh
gsh repl
```

以下のいずれかで終了します。

```text
exit
:quit
:q
```

括弧 `(`、角括弧 `[`、波括弧 `{` が閉じられていない場合は、継続プロンプト `>>` が表示されます。

## `gsh lex`

字句解析結果を確認します。

```sh
gsh lex examples/falling.gsh
```

## `gsh parse`

構文木（AST）を確認します。

```sh
gsh parse examples/falling.gsh
```

## `gsh disasm`

レジスタVMのバイトコードを確認します（定数プール・名前表・レジスタ数・
ソース位置付き）。

```sh
gsh disasm examples/falling.gsh
```

## `gsh build`

スクリプトをコンパイルし、ランタイムにバイトコードを連結した
単一exeを生成します（Windows は exe 末尾の余分なデータを無視するため、
連結したまま実行できます）。

```sh
gsh build examples/falling.gsh
./falling.exe
```

- 出力先の既定はスクリプトと同名の `.exe`（`-o` で変更可）。
- `#mode` はビルド時に記録する。
  残りの引数はすべてスクリプト引数（`args()`）になる。
- 相対パスの基準は exe のあるディレクトリ。
- 生成 exe にさらに `build` しても多重連結にならない（入替え）。
- 出力先に書けない場合（実行中の exe への上書きは Windows が錠をかけて不可）は `名前_new.exe` に出してその旨を知らせる。使うには終了後にリネームする。
- `#mode gui`（`#mode` 省略時を含む）の exe はコンソールなし（windowsgui）で出す。ダブルクリック起動で黒いコンソールが開かなくなり、それを閉じたときに同コンソールの全プロセス（本体＋実行した子）が道連れに終了する事故が起きない。`#mode cli` の exe は端末用にコンソール付きのまま。

# 字句構造

## 文の区切り

`Golash` では、文を**改行**で区切ります。

```
x = 10
y = 20
mes(x + y)
```

セミコロン `;` は字句解析では `SEMICOLON` として認識されますが、v0.8.1 のパーサでは拒否されます。

```
x = 10;   // エラー
```

文の区切りには改行を使用してください。

---

## コメント

### 行コメント

```
// コメントです
mes("hello")
```

`//` から行末までがコメントです。

### ブロックコメント

```
/*
  コメントです
*/
```

ブロックコメントは**ネスト可能**です。

```
/*
  外側
  /*
    内側
  */
  外側
*/
```

---

## 識別子とキーワード

識別子は次の形式です。

```text
[A-Za-z_][A-Za-z0-9_]*
```

次のキーワードは識別子として使用できません。

```text
def if else repeat while switch case default
as break continue return
true false
```

---

## 空白

以下は基本的に無視されます。

* スペース
* タブ
* `\r`

改行 `\n` は文の区切りとして意味を持ちます。

# リテラルと基数表記

## 整数リテラル

整数は `int64` の範囲で扱います。

`-9223372036854775808`（最小値）のみ、括弧なしの単項マイナスで記述できます（正の `9223372036854775808`・`0x8000000000000000` 単体は範囲外エラーです）。

| 種類   | 表記          | 例           | 10進値 |
| ---- | ----------- | ----------- | ---: |
| 10進数 | なし          | `42`, `007` |   42 |
| 16進数 | `0x` / `0X` | `0xFF`      |  255 |
| 2進数  | `0b` / `0B` | `0b101`     |    5 |
| 8進数  | `0o` / `0O` | `0o17`      |   15 |

プレフィクスの大文字・小文字は区別されません。

```text
0xab == 0XAB
```

字句解析時に10進数へ変換されるため、パーサや実行系は元の基数を意識する必要がありません。

`gsh lex` や `gsh parse` でも10進数として表示されます。

---

## 整数の使用例

```
mes(0xFF)          // 255
mes(0b101 & 0b011) // 1
mes(0o10 | 1)      // 9

x = 0x10
mes(x * 2)         // 32
```

---

## 不正な基数リテラル

| ソース                    | エラー                                    |
| ---------------------- | -------------------------------------- |
| `0x`                   | `malformed hexadecimal literal`        |
| `0b`                   | `malformed binary literal`             |
| `0b2`                  | `malformed binary literal`             |
| `0o8`                  | `malformed octal literal`              |
| `0xg`                  | `malformed hexadecimal literal`        |
| `0x1p3`                | `malformed hexadecimal literal`        |
| `0xFFFFFFFFFFFFFFFFFF` | `hexadecimal literal out of range`     |
| `0x1.5`                | `hexadecimal floats are not supported` |

アンダースコアによる桁区切りは v0.8.1 では使用できません。

```
0xFF_FF   // 非対応
```

数字に `_` や英字を直接続けること（`1_000`、`123abc`）、小数点の後に数字がないこと（`3.`）は字句エラーになります。

---

## 浮動小数リテラル

次の形式が利用できます。

```text
3.14
.5
2e3
1.2E-4
```

指数部には `+` または `-` を付けられます。

```text
2e+3
2e-3
```

基数プレフィクス付き浮動小数は非対応です。

範囲外の値（`1e999` など）はパースエラーになります（`Inf` にはなりません）。

---

## 文字列リテラル

文字列はダブルクォートで囲みます。

```
"hello"
"こんにちは"
```

シングルクォートは使用できません。

利用できるエスケープは以下です。

```text
\"
\\
\n
\t
\r
\0
```

未知のエスケープ、文字列中の改行、閉じられていない文字列はエラーになります。

生のNULバイトはソースのどこにも書けません（字句エラー。`\0` エスケープを使用してください）。

---

## 真偽値リテラル

```
true
false
```

---

## 配列リテラル

```
a = [1, 2, 3]
b = []
c = [[1, 2], [3, 4]]
```

配列はネストできます。

要素の型は混在可能です（voidは要素にできません）。

```
a = [1, "hello", true]
```

末尾のカンマも利用できます。

```
a = [1, 2, 3,]
```

# 型と値

`Golash` の値には次の5種類があります。関数は値ではありません（`def` で名前を登録し、呼び出しにのみ使用します）。値を返さない結果はvoidであり、代入・引数・演算に使うとエラーになります（`mes()` / `print()` は黙って飛ばします）。

| 型          | 説明             | 例            |
| ---------- | -------------- | ------------ |
| `int`      | 64bit符号付き整数    | `42`         |
| `float`    | 64bit浮動小数      | `3.14`       |
| `string`   | 文字列            | `"hello"`    |
| `bool`     | 真偽値            | `true`       |
| `array`    | 可変長配列          | `[1, 2]`     |

## intとfloat

比較・等価判定では `int` と `float` を自動的に比較できます。

```
mes(10 == 10.0)  // true
```

---

## 配列の参照セマンティクス

配列は同じ実体を共有します。

```
a = [1, 2, 3]
b = a

b[0] = 99

mes(a[0])  // 99
```

# 演算子と優先順位

## 演算子一覧

| 分類  | 演算子                                  | 説明                    |
| --- | ------------------------------------ | --------------------- |
| 算術  | `+ - * / %`                          | 加減乗除・剰余               |
| ビット | `& \| ^ ~ << >>`                     | AND・OR・XOR・NOT・左/右シフト |
| 比較  | `== != < <= > >=`                    | 等価・不等価・大小比較           |
| 論理  | `&& \|\| !`                          | 論理積・論理和・論理否定          |
| 代入  | `= += -= *= /= %= &= \|= ^= <<= >>=` | 代入・複合代入               |
| その他 | `[...] (...)`                      | 配列・関数呼び出し       |

---

## 優先順位

数字が小さいほど優先順位が高くなります。

| 優先度 | 演算子               | 結合 |
| --: | ----------------- | -- |
|   1 | `()` `[]`     | 左  |
|   2 | `-` `!` `~`       | 右  |
|   3 | `*` `/` `%`       | 左  |
|   4 | `+` `-`           | 左  |
|   5 | `<<` `>>`         | 左  |
|   6 | `<` `<=` `>` `>=` | 左  |
|   7 | `&`               | 左  |
|   8 | `^`               | 左  |
|   9 | `\|`              | 左  |
|  10 | `==` `!=`         | 左  |
|  11 | `&&`              | 左  |
|  12 | `\|\|`            | 左  |

ビット演算は等価比較より強く結合します。

```
a & b == c
```

は、

```
(a & b) == c
```

として解釈されます。

したがって、

```
if flags & 0xF0 == 0x10 {
}
```

は意図どおりマスク判定として利用できます。

---

## ビット演算

ビット演算は整数にのみ使用できます。

```
mes(6 & 3)      // 2
mes(6 | 3)      // 7
mes(6 ^ 3)      // 5
mes(~5)         // -6
mes(1 << 4)     // 16
mes(256 >> 3)   // 32
```

`float` や `string` に対して使用すると実行時エラーになります。

シフト数は `0`～`63` の範囲で指定してください。

```
-8 >> 2   // -2
```

`>>` は算術右シフトです。

---

## 整数演算の範囲

`int` の `+` `-` `*`・単項 `-`・`<<` は64bitでラップします（Goと同様）。

```
mes(9223372036854775807 + 1)  // -9223372036854775808
```

例外は `abs(MinInt64)` のみで、エラーになります（絶対値が表現できないため）。

## 文字列の結合

`+` は、左右どちらかが `string` の場合、両辺を文字列化して結合します。

```
mes("n=" + 42)      // n=42
mes([1, 2] + "")    // [1, 2]
```

void値の結合はエラーです（`"a" + f()` は `"anull"` になりません）。

## 比較の型規則

* `==` / `!=`：`int` と `float` は自動比較、他は同種のみ比較（異種は `false`、エラーではありません）
* `<` `<=` `>` `>=`：数値同士または文字列同士のみ対応（他はエラー）
* 整数除算は0方向へ切り捨てます（`-7 / 2` は `-3`）。剰余の符号は被除数に従います（`-7 % 3` は `-1`）
* 比較の連鎖（`1 < 2 < 3` など）は左結合で評価されます（`bool` と数値の比較になるため実行時エラーです）

## NaN・無限大

`NaN` と `±Inf` は値として存在しません。リテラルに書けず、以下のいずれもエラーになります。

* `0` による除算・剰余（`float` の `0.0` を含む）
* `sqrt()` の負数、`log()` の `0` 以下
* 有限でない計算結果（`1e308 * 10`、`exp(1000)`、`pow(-1, 0.5)` など）
* `float("nan")` / `float("inf")` などの変換、`int()` の範囲外変換

# 文

## 変数代入

```
x = 42
name = "Alice"
arr = [1, 2, 3]
arr[0] = 99
```

左辺には次を指定できます。

* 変数
* 配列要素

通常の代入は、見える定義があればそこを更新し、なければ現在のスコープに作ります（トップレベルではグローバル、関数内では関数ローカル）。未定義の変数の読取はエラーです。

組み込み関数と同名への代入はエラーです（`mes = 1` は不可。`def` と同じ規則）。

複合代入も利用できます。

```
x = 0
x += 1
x &= 0xFF
x <<= 2
```

複合代入では左辺のアドレスは1回だけ評価されます（`a[next()] += 1` の `next()` は1回だけ呼ばれます）。

変数の宣言は通常の代入が行います（`let` は廃止されました）。

```
x = 1
```

* 代入は「見える定義を更新し、なければ現在のスコープに作る」動作です。関数の中での代入は関数ローカル（なければ作る）か、可視のグローバルを更新します
* `if` / `repeat` / `switch` / `while` の中身はスコープを作らないため、その中の代入は囲む関数（またはグローバル）に作られます
* 同じスコープへの再代入は上書きです（`repeat` の中の代入も毎回動きます）
* 組込み関数と同名への代入はエラーです（`mes = 1` は不可）
* `let` は通常の識別子です（変数名に使用できます）。`let x = 1` のような旧記法は構文エラーになります

---

## 式文

式だけを独立した文として記述できます。

```
mes("hello")
x + 1
```

値を使用しない場合でも文として有効です。

## if

```
if x > 0 {
    mes("positive")
} else if x == 0 {
    mes("zero")
} else {
    mes("negative")
}
```

条件式は必ず `bool` 型である必要があります。

```
if 1 {
}   // エラー
```

条件分岐の連鎖は `else if` と記述してください

```
if x == 1 {
} else if x == 2 {
} else {
}
```

## repeat

### 回数指定

```
repeat 5 {
    mes("hello")
}
```

### カウンタ付き

```
repeat 3 as i {
    mes(i)
}
```

表示される値は、

```text
0
1
2
```

です。

### 配列指定

```
arr = ["a", "b"]
repeat arr as x {
    mes(x)
}
```

### インデックス付き

```
arr = ["a", "b"]
repeat arr as i, x {
    mes(str(i) + ":" + x)
}
```

結果：

```text
0:a
1:b
```

### 仕様

* 整数は `0` 以上である必要があります。
* 配列を指定すると要素を順番に反復します。
* `as x` の `x` は各要素のコピーです。
* `as i, x` の `i` は添字、`x` は要素です。
* カウンタ変数はループ内でのみ有効です。
* カウンタは読み取り専用です。
* 配列要素の変更は元の配列には書き戻されません。
* 配列を変更する場合は `a[i] = ...` を使用してください。
* 反復回数はループ開始時に確定します。
* ループ中の `push()` によって反復回数は増えません。
* 整数の `repeat` では `as i, x` は利用できません。
* ネストしたループで同じ変数名を使うと、内側の変数が一時的に外側を隠します。

## while

```
i = 0

while i < 5 {
    mes(i)
    i = i + 1
}
```

条件が `true` の間、繰り返します。

```
while true {
    // 無限ループ
}
```

ループを抜けるには `break` を使用します。

---

## switch

```
switch x {
    case 1, 2 {
        mes("one or two")
    }

    case 3 {
        mes("three")
    }

    default {
        mes("other")
    }
}
```

仕様：

* 検査対象の式は1回だけ評価されます。
* `case` は複数の値をカンマで指定できます。
* `default` は最大1個です。
* `default` の位置は自由です。
* フォールスルーはありません。
* 最初に一致した `case` だけ実行されます。
* 比較は `==` / `!=` の等価判定です。
* 配列は同一実体のときのみ等しくなります（深い比較はしません）。
* `int` と `float` は自動的に比較可能です。
* `case` 値のvoidはエラーです（検査対象と対称）。

---

## break / continue

```
repeat 10 as i {
    if i == 5 {
        break
    }

    if i == 2 {
        continue
    }

    mes(i)
}
```

### `break`

`repeat`、`while`、`switch` を終了します。

### `continue`

`repeat`、`while` の次の周回へ進みます。

`switch` 内で発生した `continue` は、外側のループへ伝播します。

ループ外の `break` / `continue` はエラーになります。

また、関数呼び出しをまたいで伝播することはありません。

意図的な中断には `assert(false, msg)` を使います。

---

## return

```
def max(a, b) {
    if a > b {
        return a
    }

    return b
}
```

`return` は関数内でのみ使用できます。

値を省略した場合はvoidを返します（使用箇所でエラーになります）。

```
return
```

## 関数定義

```
def greet(name) {
    mes("Hello, " + name)
}

def add(a, b) {
    return a + b
}

greet("Alice")
mes(add(1, 2))
```

`def` はトップレベルにのみ記述できます。関数は値として扱えません（代入・引数・`vartype` 等では変数未定義エラーになります）。呼び出し時はグローバル変数を参照できます。

パラメータの重複、組み込み関数と同名の定義・パラメータ、および同名関数の再定義はエラーになります。引数の個数は厳密に一致する必要があります。

関数内の代入は、可視スコープ（引数・作成済みローカル・グローバル）に同名があればそこを更新し、なければ関数ローカルに作ります。ブロック（`if` / `while` / `{}`）は専用スコープを作りません（`repeat` の変数のみ例外）。

再帰呼び出しは深さ10000が上限です（超過は実行時エラー）。構文のネスト（ブロック・括弧・配列/呼び出しの入れ子）は1000が上限です（超過は構文エラー）。

# 10.4 時間・実行制御

| 関数                     | 説明                 | GUIでの挙動           | CUIでの挙動           |
| ---------------------- | ------------------ | ----------------- | ----------------- |
| `sleep(ms)`            | 指定ミリ秒待機します         | 指定時間だけ待機します       | 指定時間だけ待機します       |
| `await([n])`           | `n` フレーム待機します（目標tickが表せない巨大値はエラー） | VSync tick に同期します | 約16ms × `n` 待機します |
| `tick()`               | フレームカウンタを返します      | `Update` 回数を返します  | 時刻 ÷ 16ms を返します   |
| `nanotime()`           | 単調増加するナノ秒カウンタを返します | 同じです              | 同じです              |
| `gettime(type)`        | 現在時刻の各要素を返します（下表の `0`～`7`） | 同じです              | 同じです              |
| `end([code])`          | プログラムを終了します        | ウィンドウ処理を終了します     | プログラムを終了します       |
| `assert(cond [, msg])` | 条件が偽ならエラーにします      | 同じです              | 同じです              |

### `await()`

```
await()
```

は1フレーム待機します。

```
await(3)
```

では3フレーム待機します。

ゲームループなどでは、単純な `sleep(16)` より `await()` の使用が推奨されます。

GUIでは `await()` / `sleep()` はフレーム境界として扱われます。その時点までに
`cls()` / `mes()` / `print()` で作ったテキストと、`pset()` / `line()` /
`rect()` / `ellipse()` / `paint()` / `gcopy()` 等の図形描画および `gsel()` の
切替がまとめて画面へ反映されるため、`cls()` の直後や描きかけ・裏バッファの
途中状態が1フレーム表示されることはありません（ちらつき防止）。この意味で
`await(0)` は「今のフレームを確定して表示する」操作になります。`await()` /
`sleep()` を一度も使わないスクリプトではフレーム境界が無いため、従来どおり
毎フレームの内容がそのまま反映されます。
CUIでは出力が逐次表示されるため、この差はありません。


負の座標も指定でき、画面外への描画に利用できます。

`mes()`（改行あり）は `pos()` のカーソル位置を文字の左上原点として書き始めます（`print()` 連携中は、その `print()` が描き終えた直後から続きます。`pos()` を呼ぶとカーソルはそこへ移ります）。文字列中の改行（`\n`）の2行目以降は、その行が始まった x（`pos()` があればその x、なければ `0`）から、1行ぶん下がって始まります。`mes()` 末尾の改行の後は x `0` に戻ります。文字列中のタブ（`\t`）は半角4文字分の空白として送られます（現在位置には依存しない一定幅。CUIの `mes()` では端末のタブ展開に従います）。1文字ぶんの送り幅はフォントの実測幅（MS ゴシックなら半角8px・全角16px）です。カーソルがウィンドウ下端を越えると、表示は文字と図形ごと1行上へスクロールします。

# 10.6 プロセス・環境

| 関数                    | 説明                 | GUIでの挙動                  | CUIでの挙動                  |
| --------------------- | ------------------ | ------------------------ | ------------------------ |
| `exec(name, args...)` | 外部コマンドを非同期に起動します | 起動したら `0` を返してすぐ戻ります（終了は待ちません）。入出力は透過的に表示します。子は親のコンソールを共有します（閉じると道連れに終了します） | 同じです |
| `execgui(name, args...)` | 外部コマンドをコンソールなしで非同期に起動します（GUI子プロセス用） | `exec()` と同じく `0` を返してすぐ戻ります。子にコンソールを作りません（黒窓が出ず、親子の道連れ終了もありません）。入出力は継承しますが取り込みはしません | 同じです（コンソール窓の概念がないため `exec()` と同じ動作です） |
| `pipeexec(name, args...)` | 外部コマンドを実行し標準出力を返します | 終了まで待って標準出力を文字列で返します（標準入力は切り離し、標準エラーは透過）。起動失敗・非0終了はエラーです | 同じです |
| `piperun(name, args...)` | 外部コマンドを実行し `[終了コード, 標準出力, 標準エラー]` の配列で返します | 終了まで待ちます（標準入力は切り離し）。非0終了も値です。起動失敗は `[-1, "", メッセージ]` です（エラーにしません） | 同じです |
| `getenv(name)`        | 環境変数を取得します         | 同じです                     | 同じです                     |
| `setenv(name, v)`     | 環境変数を設定します         | 現プロセスと子プロセスに反映します        | 現プロセスと子プロセスに反映します        |
| `open(target)`        | ファイル・フォルダ・URLを開きます | OSの関連付けアプリで開き、待機しません     | OSの関連付けアプリで開き、待機しません     |

`getenv()` は未設定時に `""` を返します。

`exec()` は起動成功で `0` を返してすぐ戻ります（非同期。終了コードは返しません）。出力の取り込み・終了待ちが要る場合は `pipeexec()`（終了コードが `0` 以外はエラー）を使います。終了コード・標準エラーも値で欲しい場合（try/catchがないためエディタ等ではエラーを値で扱いたい）は `piperun()` を使います。

`pipeexec()` と `piperun()` の使い分け（統合はしません。理由は下表の通りです）：

| 用途 | 使う関数 |
| ---- | ------- |
| 成功時の標準出力だけが欲しい（失敗はエラーで止めてよい） | `pipeexec()` |
| 終了コード・標準エラーも値で扱いたい（失敗しても続行したい） | `piperun()` |
| 終わらない処理を裏で走らせたい（対話的な子も可） | `exec()` |
| GUIの子をコンソールなしで裏で走らせたい | `execgui()` |

`pipeexec()` の「失敗はエラー」は try/catch のない言語ではスクリプト全体を止めます。エディタのように失敗を画面に表示して続行したい場合は `piperun()` を使います。2つを1つにまとめると「失敗時に止まるか値で返すか」のどちらかが書けなくなるため、分けています。

# 10.14 GUI描画

描画位置は `pos()` に統一されています。`pset()` / `pget()` / `paint()` は引数を取らず `pos()` の位置に描画・読取・シードし、`line(x2,y2)` は `pos()` から `(x2,y2)` へ引き、`rect(w,h)` は `pos()` を左上として `w x h` を塗り、`ellipse(w,h [,fill])` は `pos()` を中心に描きます。描画コマンドは `pos()` を移動しません（続けて描く場合はその都度 `pos()` します）。`gcopy()` の転送先も `pos()`（現在位置）です。複数面を一括指定する `gquad()` のみ絶対座標の配列のままです。

| 関数                      | 説明            | GUIでの挙動          | CUIでの挙動             |
| ----------------------- | ------------- | ---------------- | ------------------- |
| `pset()`             | 1ピクセルを描画します   | `pos()` の位置に現在色で1ピクセル描画します   | GUI描画は行われません        |
| `pget()`             | 1ピクセルの色を取得します | `pos()` の位置の色を `0xRRGGBB` 整数（`r*65536+g*256+b`）で返します。範囲外はエラーです | GUI描画は行われません        |
| `line(x2,y2)`     | 直線を描画します      | `pos()` の位置から `(x2,y2)` へ現在色で直線を描画します     | GUI描画は行われません        |
| `rect()`                | 全画面を塗りつぶします   | 現在色で画面全体を塗ります    | GUI描画は行われません        |
| `rect(w,h)`     | 矩形を塗りつぶします    | `pos()` の位置を左上として `w x h` を塗ります（負の辺は逆向きに正規化されます）        | GUI描画は行われません        |
| `ellipse(w,h [,fill])` | 楕円を描画します       | `pos()` の位置を中心に全幅 `w`・全高 `h` の楕円を描画します（`w == h` で真円、`w`・`h` は `0` 以上）          | GUI描画は行われません        |
| `gcopy(src,sx,sy,w,h [,zx,zy [,deg]])` | バッファの領域を転送します | 現在位置へ画像領域をコピーします。`zx,zy` 指定で拡大・縮小、`deg` 追加で領域中心回転（中心は現在位置）します | GUI描画は行われません |
| `gquad(tex,xs,ys,us,vs,lights)` | バッファの四角形を自由四角形へ写します（`gsquare()` の後継） | 画像の参照元ピクセル（`us`/`vs`）を変換先4点（`xs`/`ys`、時計回り・反時計回りの順）へ透視補正付きで写します。`lights` は頂点毎の `0xRRGGBB`（Gouraud、同値はフラット）。空の面は描画なし、縮退・裏返りはエラーです | GUI描画は行われません |

各配列は1面あたり4要素のフラット配列です。4の倍数要素（`xs` と同長の `ys/us/vs/lights`）でN面を1コマンドで描画します（上限65536面）。5配列すべてが空の場合は何も描画しません（面を間引いたループ結果をそのまま渡せます）。例：

```text
gquad(1,
    [300, 420, 390, 270], [300, 300, 380, 380],   // xs, ys: 変換先4点
    [0, 60, 60, 0], [0, 0, 40, 40],               // us, vs: 参照元4点
    [16777215, 16777215, 8388608, 8388608])       // lights: 上は白、下は暗く
```

| `gmode(mode)`           | 合成モードを変更します   | `0` 通常、`1` 加算    | GUI描画は行われません        |
| `picload(path)`         | 画像を読み込みます（各辺 4096 まで） | 新しいバッファIDを返します   | GUI画像バッファとしては使用しません |

### `input()` の即時モード（GUI）

GUI の `input()` はブロックせず、前回呼出以降に入力された確定文字列を返します（IME確定分を含みます。変換中は画面左上の固定欄に表示されます）。OS のロケール依存変換（配列・shift・caps 対応）で。新しい入力（OS のキーリピートで届く文字や IME 確定分を含む）は届くたびにそのまま返します。何もなければ `""` です。毎フレーム呼び出すことを想定しています。

Backspace・Tab・Enter・Esc・Delete は制御文字（コード `8`・`9`・`13`・`27`・`127`、同じリピート付き）として返るため、`asc()` と組み合わせて行編集が組めます（`"\r"` との比較、または `asc(k) == 13` で確定判定）。矢印・ファンクションキー等の非文字キーは現れません（物理キーは `getkey()` を使います）。

```
s = ""
while true {
    k = input()
    if k != "" {
        if k == "\r" {
            break
        }
        s = s + k
    }
    await()
}
```

リピート間隔（60fpsでの目安）：文字入力は OS のキーリピート設定に従います。Backspace 等の制御文字は初回即時・約400ms後から約33msごとに再送します。

注意：

* GUI の `input()` は引数を取りません（プロンプトは `mes()` で表示してください）
* `inputbox` フォーカス中は `""` です（ボックスがキー所有権を持ちます）
* IME 変換中は制御キーを返しません（変換の編集・確定が優先されます）
* CUI の `input([prompt])` は従来通り行単位のブロッキング入力です（EOFは `""` になります）

# プリプロセッサ

## `#define`

```
#define MAX 0x10
#define NAME "Alice"
```

定義できるのは1個のリテラルです。

利用可能な型：

* 整数
* 小数
* 文字列
* 真偽値

数値には `-` を付けられます。

```
#define N -3
```

式は指定できません。

```
#define N 2 * 3   // 非対応
```

定義より前の位置（`#include` 展開順のストリームで前にない場所）には適用されません。

```
// lib.gsh
#define GREET "hi"

// main.gsh
#include "lib.gsh"
mes(GREET)   // ライブラリの定義は #include より後で使える
```

`#include` で取り込んだライブラリの定義は、その `#include` 行より後の行（親ファイル・後のきょうだい）から使えます。逆に、親の後の行の定義が、既に展開済みのライブラリに届くことはありません。

再定義はファイルの垣根を越えてエラーです（ライブラリと同名の定義も不可）。

キーワード・`true` / `false`・組み込み関数と同名の定義はエラーです（死に定義・組込の乗っ取りを防止するため）。

トークン単位で置換します。

```
#define MAX 100   // MAXIMUMは100IMUMにならない
```

値を省略すると連番の整数定数になります。

```
#define COLOR_RED
#define COLOR_GREEN
#define COLOR_BLUE
mes(COLOR_GREEN)  // 1
```

* カウンタは `0` 開始で、無値形ごとに +1 されます。
* 明示の整数でカウンタはその値+1にリセットされます（`#define B 5` の次は `6`）。
* 整数以外（小数・文字列・真偽値）はカウンタに影響しません。
* 非活性区間の行はカウンタを進めません。
* カウンタは `#include` 展開順のストリームで共有されます（ライブラリの無値形も順に番号付けされます）。

## `#define` の注意

`#define` はテキスト置換です。

そのため、

```
#define MAX 100
```

とすると、同名の識別子が置換対象になります。

そのため、`#define` はその入力内でのみ有効です。連番カウンタも同じ寿命です。

## GUIの実装

GUIバックエンドは `gui/` ディレクトリに実装されています。

主な構成：

```text
Ebiten
ebitenui
```

画面描画は `ebiten.Image` へのキューイング方式です。

`ReadPixels` / `WritePixels` はゲームスレッド上で実行されます。

テキスト描画には OS のシステムフォントを使用します（フォントファイルは同梱していません）。

Windows では既定で MS ゴシック（16px で半角 8px・全角 16px のセルグリッドに一致）を、次点で游ゴシック・メイリオ・Noto Sans JP・BIZ UD Gothic などを自動検出します。macOS は Osaka・ヒラギノ角ゴ、Linux は Migu 1M・VL Gothic・IPAゴシック、次点で Noto Sans CJK などを探します。いずれも見つからなければ候補順の次へフォールバックします。

環境変数 `GOLASH_FONT` に `.ttf` / `.otf` / `.ttc` ファイルのパスを指定すると、そのフォントを優先します。

`font(spec)` の名前解決順は、スクリプト脇→カレントディレクトリ→システムフォントです。Windows では `C:\Windows\Fonts` に加え、管理者権限なしインストール先の `%LOCALAPPDATA%\Microsoft\Windows\Fonts` も検索します。スクリプト脇・カレントではファイル名そのまま・拡張子補完・前方一致の順で探すので、拡張子なしの指定もそのまま見つかります（例 `PlemolJP`→`PlemolJP-Regular.ttf`）。システムフォントでは拡張子なしの指定を前方一致で探し（同例）、Regular体を優先します。

システムフォントが見つからない環境では、GUI バックエンドの生成時にエラーになります。

音声再生には Ebiten の `audio` パッケージを使用します。

`audio.Context` はプロセス内で1つだけ共有されます。

## IMEの実装状況

IMEによる日本語入力では、変換確定後の文字列は `input()` の即時ストリームまたはフォーカス中の `inputbox` に渡され、変換中の文字列は画面左上の固定欄に表示されます（`ime()` の使い方は 10.18 を参照）。

### 候補ウィンドウ・変換中文字列の位置について

変換中文字列は画面左上隅の固定欄（白地・灰枠・黒文字、変換文節に太下線・他に細下線。縦は1行ぶん＋2px）に、候補窓はその直下の画面左上に固定表示されます（`textinput.Field.HandleInputWithBounds` に渡す矩形基準。Windows `ImmSetCandidateWindow`・macOS・Web のいずれもこの矩形基準）。caret追従・手動の位置指定はありません（`imepos()` は廃止）。

# まとめ：GUIとCUIの使い分け

`Golash` の標準実行モードはGUIです（`#mode` 省略時はウィンドウが開きます）。端末で実行するには `#mode cli` を指定します。

```text
CUI
├─ 標準入出力
├─ ファイル操作
├─ 文字列操作
├─ 数値計算
├─ 配列
├─ HTTP
├─ プロセス・環境変数
└─ スクリプト制御
```

GUIビルドでは、これに加えて、

```text
GUI
├─ ウィンドウ
├─ 2D描画
├─ キーボード
├─ マウス
├─ ゲームパッド
├─ タッチ
├─ IME
├─ 音声
└─ ウィジェット
```

を利用できます。

特にゲームやGUIアプリケーションでは、

```
while true {
    // 入力
    if getkey(37) {
        x -= 1
    }

    // 更新
    x += 1

    // 描画
    cls()
    pos(x, y)
    pset()

    // 次のフレームまで待つ
    await()
}
```

のように、`入力 → 更新 → 描画 → await()` の流れで記述できます。

# v0.8.1の基本方針

`Golash` v0.8.1 では、曖昧さを減らすため、以下を特に重視しています。

* 条件式は `bool` に限定します。
* ビット演算は整数に限定します。
* エラーには可能な限りファイル名・行・列を付けます。
* 改行を文の区切りとして使用します。
* 配列の動作を明確に定義します。
* GUIとCUIの違いを、実行環境ではなく組み込み関数単位でも確認できるようにしています。
* 整数演算のオーバーフローはラップします（`abs(MinInt64)` のみ例外）。
* `NaN`・`±Inf` は値として存在しません（生成・変換はすべてエラー）。
* 範囲外アクセス・黙認の切り詰めはエラーに統一します。
* 再帰は深さ10000、構文ネストは1000が上限です。

サンプルプログラムについては `examples/`（落ちものパズルの作例）、言語の回帰用フィクスチャについては `testdata/parity/`、仕様の回帰確認については各テストファイルを参照してください。

今後のバージョンアップでは、仕様変更があった組み込み関数について、GUI・CUIの両方の挙動を本表へ反映します。
